1.1GA4 คือ “สมุดบันทึกพฤติกรรม” ของเว็บ

ลองนึกถึงสาขาธนาคารสักแห่ง ผู้จัดการสาขาอยากรู้ว่าวันนี้มีคนเดินเข้ามากี่คน แต่ละคนมาเพราะอะไร (เห็นป้ายโฆษณา? เพื่อนแนะนำ?) เดินไปโต๊ะไหน หยิบโบรชัวร์บัตรใบไหน และกรอกใบสมัครจนจบหรือเปล่า

GA4 (Google Analytics 4) ทำแบบเดียวกันกับเว็บไซต์ เป็นเครื่องมือฟรีของ Google ที่จดว่ามีคนเข้าเว็บกี่คน มาจากช่องทางไหน และทำอะไรบนเว็บบ้าง แล้วสรุปออกมาเป็นรายงานและกราฟ

🏦
ทำไมบริษัทบัตรเครดิตถึงสนใจ GA4 มาก เว็บบริษัทบัตรเครดิตและสินเชื่อมีเป้าหมายชัดเจน คือให้คน “สมัคร” GA4 ช่วยตอบคำถามที่มีผลกับเงินค่าโฆษณาโดยตรง เช่น
  • โฆษณา Facebook หรือ Google Ads ตัวไหนพาคนมาสมัครได้จริง
  • คนกดปุ่มสมัครแล้วหลุดออกไปที่ขั้นตอนไหนของฟอร์ม
  • คนสมัครผ่านมือถือหรือคอมพิวเตอร์มากกว่ากัน

1.4ใน GA4 ทุกอย่างคือ “Event”

ทุกการกระทำบนเว็บถูกบันทึกเป็น Event (เหตุการณ์) เช่น เปิดหน้า = page_view, เลื่อนลงถึงล่างสุด = scroll, ส่งใบสมัครสำเร็จ = generate_lead

แต่ละ event มี Parameter (รายละเอียดประกอบ) ติดไปด้วย ให้นึกภาพพัสดุหนึ่งกล่อง ชื่อบนกล่องคือชื่อ event ส่วนป้ายที่แปะอยู่ข้างกล่องคือ parameter

ถ้าเขียนเป็นโค้ด จะหน้าตาประมาณนี้ (วันที่ 4 คุณจะได้เขียนเอง):

JavaScript · ตัวอย่างข้อมูล 1 event
{
  event: 'apply_click',       // ← ชื่อ event
  card_type: 'cashback',     // ← parameter
  button_location: 'hero'    // ← parameter
}

2.1เปิดหน้าเว็บฝึกด้วย Live Server

ถ้าดับเบิลคลิกไฟล์ HTML เบราว์เซอร์จะเปิดเป็น file:///C:/... ซึ่ง GA4 เก็บคุกกี้ไม่ได้ และเครื่องมือทดสอบของ GTM ก็เชื่อมต่อไม่ได้ เราจึงต้องเปิดผ่าน “เซิร์ฟเวอร์จำลอง” ในเครื่อง

  1. เปิด VS Code → File›Open Folder… → เลือกโฟลเดอร์ GoogleAnalytics4
  2. กดไอคอน Extensions (Ctrl+Shift+X) ค้นหา Live Server (ของ Ritwick Dey) แล้วกด Install
  3. คลิกขวาที่ไฟล์ practice-page.html → Open with Live Server
  4. Chrome จะเปิด http://127.0.0.1:5500/practice-page.html ใช้ลิงก์นี้ตลอดคอร์ส
🌐
อยากได้ลิงก์จริงไว้ให้คนอื่นเปิดดู (เช่น โชว์ตอนสัมภาษณ์)?ลากโฟลเดอร์ไปวางที่ app.netlify.com/drop จะได้ลิงก์ https://...netlify.app ฟรีในไม่กี่วินาที

2.2สร้างบัญชี GA4 ทีละขั้น

  1. ไปที่ analytics.google.com ล็อกอินด้วย Gmail แล้วกด Start measuring
  2. Account creation — Account name: DemoCard Practice ส่วน Data sharing settings ปล่อยตามค่าเริ่มต้น → Next
  3. Property creation — Property name: DemoCard Website · Reporting time zone: Thailand (GMT+07:00) · Currency: Thai Baht (฿) → Next
  4. Business details — Industry category: Finance · Business size: เลือกตามจริง (ฝึกเลือก Small ได้) → Next
  5. Business objectives — เลือก Generate leads (หาลูกค้าที่สนใจ ตรงกับเว็บสมัครบัตร) → Create → เลือกประเทศ Thailand แล้วยอมรับ Terms of Service
  6. Data collection — เลือกแพลตฟอร์ม Web
  7. Website URL: ใส่ชื่อสมมติได้ เช่น democard-practice.com (ช่องนี้ใช้ตั้งชื่ออย่างเดียว ไม่ได้จำกัดว่าเก็บข้อมูลจากเว็บไหน) · Stream name: DemoCard Web · เปิด Enhanced measurement ค้างไว้ → Create & continue
  8. หน้า Web stream details จะเปิดขึ้นมา คัดลอก Measurement ID (G- ตามด้วยตัวอักษร) เก็บไว้

2.4ติดตั้งโค้ด gtag.js

ในหน้า Web stream details กด View tag instructions → แท็บ Install manually จะได้โค้ดหน้าตาแบบนี้ (รหัส G- จะเป็นของคุณ)

HTML · วางใน <head> ของ practice-page.html ตรงจุดที่เขียนว่า “วันที่ 2”
<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());

  gtag('config', 'G-XXXXXXXXXX');
</script>
บรรทัดทำหน้าที่อะไร
<script async src=...>โหลดไลบรารีของ Google (async = ไม่ทำให้หน้าเว็บโหลดช้า)
window.dataLayer = ...สร้าง “กล่องจดหมาย” ไว้ส่งข้อมูลให้ Google (วันที่ 4 จะใช้กล่องนี้)
gtag('config', 'G-...')บอกว่าส่งข้อมูลไป property ไหน และส่ง page_view ทันที
  1. เปิด practice-page.html ใน VS Code หาคอมเมนต์ วันที่ 2: วางโค้ด gtag ตรงนี้
  2. วางโค้ดแทนบรรทัดนั้น แล้วเปลี่ยน G-XXXXXXXXXX ทั้ง 2 จุดเป็นรหัสของคุณ

4.3วิธีที่ 1: วัดคลิกแบบไม่ต้องแก้โค้ด (Click trigger)

GTM ดักจับการคลิกบนหน้าเว็บได้เอง เราแค่บอกว่า “ถ้าคลิกโดนลิงก์ที่มี ID นี้ ให้ส่ง event” ในหน้าเว็บฝึก ลิงก์ “ดูสิทธิประโยชน์ทั้งหมด” มี id="benefits-link" อยู่แล้ว

  2. สร้าง trigger: Triggers›New → ชื่อ Click - benefits link → Trigger type: Click - Just Links → เลือก Some Link Clicks → ตั้งเงื่อนไข Click ID equals benefits-link → Save
  3. สร้าง tag: Tags›New → ชื่อ GA4 - Event - benefits_click → Tag type: Google Analytics: GA4 Event → Measurement ID: G-XXXXXXXXXX → Event Name: benefits_click → Triggering: Click - benefits link → Save
  4. เปิด Preview → คลิกลิงก์บนหน้าเว็บฝึก → ใน Tag Assistant จะเห็นเหตุการณ์ Link Click และ tag ของเราอยู่ใน Tags Fired

4.4วิธีที่ 2: dataLayer.push วิธีที่บริษัทใหญ่ใช้กับปุ่มสำคัญ

dataLayer คือ JavaScript array ธรรมดา (window.dataLayer) ทำหน้าที่เป็น “กล่องจดหมาย” ระหว่างเว็บกับ GTM เว็บหยอดจดหมาย (object) ลงกล่อง แล้ว GTM คอยเปิดอ่าน ข้อดีคือส่งข้อมูลธุรกิจที่หน้าจอไม่ได้แสดงไปด้วยได้ เช่น ผู้ใช้เลือกบัตรประเภทไหน และไม่พังเวลาเปลี่ยนดีไซน์

โค้ดนี้มีอยู่ใน practice-page.html แล้ว ลองเปิดดูได้:

JavaScript · ใน practice-page.html
document.getElementById('hero-apply').addEventListener('click', function () {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push({
    event: 'apply_click',        // ← key "event" พิเศษ: GTM ใช้ตัดสินว่า Custom Event ไหนเกิด
    card_type: 'not_selected',
    button_location: 'hero'
  });
});

ถ้าทำเว็บด้วย React / Next.js (หรือ vibe code) หน้าตาจะประมาณนี้:

React (JSX)
<button
  onClick={() => window.dataLayer?.push({
    event: 'apply_click',
    card_type: 'cashback',
    button_location: 'card_list'
  })}
>
  สมัครเลย
</button>
🤖
ใช้กับ vibe codeสั่ง AI ได้เลย เช่น “ตอนกดปุ่มสมัคร ให้ push dataLayer event ชื่อ apply_click พร้อม card_type และ button_location ห้ามส่งข้อมูลส่วนตัว” แล้วเปิด Preview ตรวจทุกครั้งว่าค่าที่ส่งออกไปถูกจริง

ตั้งค่าใน GTM: 3 ชิ้น (Variable → Trigger → Tag)

  1. Variable: Variables›User-Defined Variables›New → ชื่อ DLV - card_type → ประเภท Data Layer Variable → Data Layer Variable Name: card_type → Save
    ทำซ้ำอีก 2 ตัว: DLV - button_location (ชื่อ button_location) และ DLV - income_range (ชื่อ income_range) ชื่อต้องสะกดตรงกับในโค้ดทุกตัวอักษร
  2. Trigger: Triggers›New → ชื่อ CE - apply_click → ประเภท Custom Event → Event name: apply_click → This trigger fires on: All Custom Events → Save
  3. Tag: Tags›New → ชื่อ GA4 - Event - apply_click → Google Analytics: GA4 Event → Measurement ID: G-XXXXXXXXXX → Event Name: apply_click → เปิด Event Parameters แล้วกด Add parameter 2 แถว (ดูภาพ) → Triggering: CE - apply_click → Save
🧠
ทริคมือโปร: เก็บ Measurement ID ไว้ใน Variableสร้าง Variable ประเภท Constant ชื่อ Const - GA4 ID ใส่ค่า G-XXXXXXXXXX แล้วใช้ {{Const - GA4 ID}} ในทุก tag วันไหนต้องเปลี่ยน ID ก็แก้แค่ที่เดียว

ทำซ้ำกับ generate_lead: สร้าง trigger CE - generate_lead (Custom Event ชื่อ generate_lead) และ tag GA4 - Event - generate_lead ที่ส่ง parameter card_type กับ income_range ในหน้าเว็บฝึก event นี้จะถูก push เฉพาะตอนส่งฟอร์มผ่านการตรวจแล้วเท่านั้น

❌ ห้ามทำเด็ดขาด
dataLayer.push({
  event: 'generate_lead',
  full_name: 'สมชาย ใจดี',
  phone: '0812345678'
});
✅ แบบที่ถูกต้อง

  event: 'generate_lead',

6.1PII: ข้อมูลที่ห้ามส่งเข้า GA4 เด็ดขาด

PII (Personally Identifiable Information) คือข้อมูลที่ระบุตัวคนได้ นโยบายของ Google ห้ามส่ง PII เข้า Google Analytics ถ้าส่งเข้าไปแล้ว อาจต้องลบข้อมูลทิ้งทั้งชุด และยังเสี่ยงผิดกฎหมายคุ้มครองข้อมูลด้วย

❌ ห้ามส่ง

  • ชื่อ-นามสกุล
  • เบอร์โทรศัพท์
  • อีเมล
  • เลขบัตรประชาชน
  • เลขบัตรเครดิต / เลขบัญชี
  • ที่อยู่

✅ ส่งได้

  • ประเภทบัตรที่เลือก (cashback)
  • ช่วงรายได้ (30k_50k) ไม่ใช่ตัวเลขจริง
  • ขั้นตอนที่ทำถึง (step_2)
  • ตำแหน่งปุ่ม (hero)
  • ผลลัพธ์ (success / error)

⚠️ ทางรั่วที่คนไม่ทันระวัง: URL

GA4 เก็บ URL ของทุกหน้าไว้ใน page_location โดยอัตโนมัติ ถ้าฟอร์มส่งข้อมูลด้วย method="GET" หรือ dev เขียนโค้ดให้ redirect พร้อมข้อมูลติด URL ไปด้วย PII จะรั่วเข้า GA4 ทันทีโดยไม่มีใครตั้งใจ

❌ URL หน้าขอบคุณแบบนี้ = ข้อมูลรั่ว
https://democard.co.th/thank-you?name=somchai&phone=0812345678&email=somchai@mail.com
  • วิธีป้องกัน: ฟอร์มใช้ POST, ห้ามใส่ข้อมูลส่วนตัวใน URL, ห้ามใส่ชื่อลูกค้าในชื่อหน้า (<title>สวัสดีคุณสมชาย</title>) และ review ทุก dataLayer.push ก่อนขึ้นจริง
  • วิธีตรวจ: Explore → Free form → ใส่ dimension Page location แล้วค้นหาคำว่า @, phone=, email=

6.3Consent Mode v2: ให้ tag ฟังคำตอบจากแบนเนอร์

Consent Mode คือวิธีที่ Google tag ใช้รู้ว่าผู้ใช้อนุญาตอะไรไว้บ้าง ผ่านสถานะ 4 ตัว

สถานะควบคุมอะไร
analytics_storageคุกกี้สำหรับวิเคราะห์ (GA4)
ad_storageคุกกี้สำหรับโฆษณา
ad_user_dataอนุญาตให้ส่งข้อมูลผู้ใช้ไป Google เพื่อใช้ทำโฆษณา
ad_personalizationอนุญาตให้ทำโฆษณาเฉพาะบุคคล (remarketing)
JavaScript · ต้องรันก่อนโค้ด GTM (practice-page.html มีให้แล้ว)
window.dataLayer = window.dataLayer || [];
function gtag(){ dataLayer.push(arguments); }

// 1) ค่าเริ่มต้น: ยังไม่อนุญาตอะไรเลย
gtag('consent', 'default', {
  analytics_storage: 'denied',
  ad_storage: 'denied',
  ad_user_data: 'denied',
  ad_personalization: 'denied',
  wait_for_update: 500
});

// 2) เมื่อผู้ใช้กด “ยอมรับ” บนแบนเนอร์
gtag('consent', 'update', {
  analytics_storage: 'granted',
  ad_storage: 'granted',
  ad_user_data: 'granted',
  ad_personalization: 'granted'
});
แบบทำงานยังไง
Basicไม่โหลด Google tag เลยจนกว่าผู้ใช้จะกดยอมรับ
Advancedโหลด tag ไว้ก่อน ถ้ายังไม่ยินยอมจะส่งสัญญาณแบบไม่มีคุกกี้ (cookieless pings) แทน แล้ว Google ใช้สัญญาณนี้ประมาณการข้อมูลส่วนที่ขาดไป

แต่ละบริษัทเลือกแบบตามนโยบายของตัวเอง ในสัมภาษณ์แค่อธิบายได้ว่าสองแบบต่างกันยังไงก็พอ

  1. ลองบนหน้าเว็บฝึก: เปิด practice-page.html หาบรรทัด var USE_CONSENT_MODE = false; แล้วเปลี่ยนเป็น true → Save
  2. รีเฟรชหน้า จะมีแบนเนอร์คุกกี้ขึ้นมา (ยังไม่ต้องกด)
  3. เปิด GTM Preview → ใน Tag Assistant คลิกเหตุการณ์ Consent Initialization → แท็บ Consent จะเห็นว่าทุกตัวเป็น Denied
  4. กด “ยอมรับทั้งหมด” บนหน้าเว็บ แล้วดูแท็บ Consent อีกครั้ง ค่า On-page Update จะเปลี่ยนเป็น Granted
  5. ลองกด “ตั้งค่าคุกกี้ใหม่” ที่ท้ายหน้าเว็บ แล้วเลือก “ปฏิเสธ” เพื่อเปรียบเทียบ จบแล้วเปลี่ยนกลับเป็น false ถ้าอยากเก็บข้อมูลง่ายๆ ต่อ

7.217 คำถามยอดฮิต

ลองตอบออกเสียงเองก่อน แล้วค่อยกดเปิดดูแนวคำตอบ

Q1GA4 คืออะไร ต่างจาก Universal Analytics ยังไง

GA4 เป็นเครื่องมือวัดผลเว็บและแอปของ Google ที่ใช้โมเดลแบบ event คือทุกการกระทำเป็น event ที่มี parameter แนบมา ส่วน Universal Analytics รุ่นเก่านับแบบ pageview และ session และหยุดเก็บข้อมูลไปตั้งแต่กลางปี 2023 GA4 รวมเว็บกับแอปไว้ใน property เดียวได้ มีเมนู Explore สำหรับวิเคราะห์เชิงลึก และรองรับเรื่องความเป็นส่วนตัวอย่าง Consent Mode

Q2Event กับ Parameter ต่างกันยังไง ยกตัวอย่าง

Event คือสิ่งที่เกิดขึ้น เช่น apply_click ส่วน Parameter คือรายละเอียดของสิ่งนั้น เช่น card_type = cashback และ button_location = hero ถ้าเป็น parameter ที่ตั้งเอง ต้องลงทะเบียนเป็น custom dimension ก่อนถึงจะใช้ในรายงานได้

Q3Key event คืออะไร ตั้งยังไง

Key event คือ event ที่สำคัญต่อเป้าหมายธุรกิจ เช่น ส่งใบสมัครสำเร็จ เดิมเรียกว่า conversion ตั้งได้ที่ Admin › Data display › Key events โดยใส่ชื่อ event หรือกดดาวในรายการ Events พอตั้งแล้ว รายงานจะมีคอลัมน์ key events และ key event rate ให้ดูว่าช่องทางไหนพาคนมาทำเป้าหมายได้

Q4ทำไมควรใช้ GTM แทนการฝังโค้ดลงเว็บตรงๆ

GTM รวม tag ทุกตัวไว้ที่เดียว ทั้ง GA4, Meta Pixel, Google Ads ทีมเพิ่มหรือแก้ tag ได้โดยไม่ต้องรอ deploy เว็บ มี Preview ให้ทดสอบก่อน มี version ย้อนกลับได้ และจัดการ consent ได้รวมศูนย์ แต่ต้องมีการควบคุม เช่น กำหนดว่าใครมีสิทธิ์ publish และตั้งชื่อให้เป็นระบบ

Q5Tag, Trigger, Variable คืออะไร

ประโยคเดียวคือ “เมื่อ Trigger เกิดขึ้น ให้ทำ Tag โดยใช้ข้อมูลจาก Variable” เช่น เมื่อมี Custom Event apply_click (trigger) ให้ส่ง GA4 event (tag) พร้อม card_type ที่ดึงจาก Data Layer Variable (variable)

Q6ถ้าได้โจทย์ “วัดว่ามีคนกดปุ่มสมัครบัตรกี่ครั้ง แยกตามประเภทบัตร” จะทำยังไง

1) ถามทีมก่อนว่าจะเอาข้อมูลไปตอบคำถามอะไร 2) เขียน tracking plan: event apply_click, parameter card_type และ button_location 3) ให้ frontend push dataLayer ตอนคลิก 4) ใน GTM สร้าง Data Layer Variable, Custom Event trigger และ GA4 Event tag 5) ทดสอบใน Preview และ DebugView 6) Publish พร้อมตั้งชื่อเวอร์ชัน 7) ลงทะเบียน card_type เป็น custom dimension 8) ทำรายงานหรือ exploration ให้ทีม

คำถามนี้คือหัวใจของงาน ถ้าตอบได้เป็นขั้นตอนแบบนี้ จะดูมีประสบการณ์มาก

Q7dataLayer คืออะไร ทำไมดีกว่าการจับคลิกจาก CSS class

dataLayer เป็น JavaScript array ที่เว็บใช้ส่งข้อมูลให้ GTM ข้อดีคือไม่พังเมื่อเปลี่ยนดีไซน์หรือข้อความบนปุ่ม ส่งข้อมูลธุรกิจที่หน้าจอไม่ได้แสดงได้ เช่น ประเภทบัตรที่เลือก และเหมาะกับเว็บ React หรือ Next.js ที่ DOM เปลี่ยนบ่อย ข้อเสียคือต้องให้ dev ช่วยเขียนโค้ด จึงต้องมี tracking plan ที่ชัดเจน

Q8จะตรวจยังไงว่า tracking ทำงานถูกต้อง

ใช้ GTM Preview หรือ Tag Assistant ดูว่า tag ทำงานถูกจังหวะไหม และค่า variable ถูกไหม ต่อด้วย GA4 DebugView ดูว่า event กับ parameter เข้ามาครบ ดู Realtime และเปิด DevTools แท็บ Network ดู request /g/collect หลังผ่านไป 24–48 ชั่วโมงก็กลับมาเช็กในรายงานจริงอีกครั้ง

Q9ติดตั้งแล้วแต่ข้อมูลไม่ขึ้นในรายงาน จะไล่ปัญหายังไง

ไล่จากต้นทาง: โค้ด GTM อยู่บนหน้าไหม → Publish แล้วหรือยัง → Measurement ID ถูกไหม → trigger ทำงานไหม → ถูก ad blocker บล็อก หรือ consent เป็น denied หรือเปล่า → request collect ส่งออกไปไหม → รายงานมาตรฐานต้องรอ 24–48 ชั่วโมง → parameter ที่ตั้งเองลงทะเบียน custom dimension หรือยัง → filter internal traffic กรองตัวเราทิ้งไปหรือเปล่า

Q10Users กับ Sessions ต่างกันยังไง แล้ว Engagement rate คืออะไร

Users คือจำนวนคน (นับตามเบราว์เซอร์หรืออุปกรณ์) Sessions คือจำนวนรอบที่เข้ามา คนเดียวเข้า 3 รอบ = 1 user 3 sessions ส่วน Engagement rate คือ % ของ session ที่มีส่วนร่วมจริง คืออยู่เกิน 10 วินาที หรือดู 2 หน้าขึ้นไป หรือเกิด key event และ bounce rate ใน GA4 ก็คือส่วนกลับของค่านี้

Q11UTM คืออะไร ใช้ตอนไหน

UTM คือ parameter ที่ต่อท้ายลิงก์เพื่อบอก GA4 ว่าคนมาจากไหน หลักๆ มี utm_source, utm_medium, utm_campaign และมี utm_content, utm_term เสริม ใช้กับลิงก์ที่ส่งออกไปข้างนอก เช่น โฆษณา, LINE OA, SMS, อีเมล ต้องตั้งชื่อเป็นตัวพิมพ์เล็กให้ตรงกันทั้งทีม และห้ามใช้กับลิงก์ภายในเว็บตัวเอง

Q12หัวหน้าถามว่าแคมเปญไหนพาคนสมัครบัตรได้ดีที่สุด จะดูยังไง

ไปที่ Traffic acquisition เปลี่ยน dimension เป็น Session campaign หรือ source/medium แล้วเลือกคอลัมน์ Key events ให้นับเฉพาะ generate_lead ดูทั้งจำนวนและ session key event rate เพราะช่องทางที่คนเยอะอาจสมัครน้อย ถ้าจะดูว่าแต่ละช่องทางมีส่วนช่วยแค่ไหนตลอดเส้นทางของลูกค้า ให้ดูรายงาน attribution ในส่วน Advertising เพิ่ม

Q13Funnel exploration ใช้ทำอะไร

ใช้ดูว่าคนผ่านแต่ละขั้นตอนไปกี่ % และหลุดตรงไหน เช่น เข้าเว็บ → กดสมัคร → ส่งใบสมัคร ถ้าหลุดมากหลังกดสมัคร แปลว่าฟอร์มน่าจะมีปัญหา แยก breakdown ตามอุปกรณ์ได้ เพื่อดูว่ามือถือมีปัญหามากกว่าหรือเปล่า แล้วเสนอให้ปรับแล้ววัดผลซ้ำ

Q14ข้อมูลแบบไหนห้ามส่งเข้า GA4 จะป้องกันยังไง

ห้ามส่ง PII เช่น ชื่อ, เบอร์โทร, อีเมล, เลขบัตรประชาชน, เลขบัตรเครดิต เพราะผิดนโยบาย Google และเสี่ยงผิด PDPA วิธีป้องกันคือกำหนดใน tracking plan ให้ชัดว่าส่ง parameter อะไรบ้าง ใช้ค่าเป็นช่วงแทนตัวเลขจริง ให้ฟอร์มใช้ POST และไม่ใส่ข้อมูลใน URL review dataLayer ก่อนขึ้นจริง และสุ่มตรวจ page_location เป็นระยะ

Q15Consent Mode คืออะไร เกี่ยวกับ PDPA ยังไง

Consent Mode เป็นกลไกที่ทำให้ Google tag ทำงานตามความยินยอมที่ผู้ใช้เลือกบนแบนเนอร์ ผ่านสถานะ analytics_storage, ad_storage, ad_user_data, ad_personalization เริ่มจาก default เป็น denied แล้ว update เป็น granted เมื่อผู้ใช้ยอมรับ ช่วยให้เว็บเคารพการตัดสินใจของผู้ใช้ตามแนวทาง PDPA ส่วนนโยบายว่าต้องขออะไร เป็นงานของฝ่ายกฎหมาย หน้าที่ของเราคือติดตั้งให้ถูกต้องและทดสอบให้แน่ใจ

Q16เว็บ React / Next.js (SPA) จะวัด page_view ยังไง

SPA เปลี่ยนหน้าโดยไม่ reload ทั้งหน้า Enhanced measurement ของ GA4 มีตัวเลือก “Page changes based on browser history events” ที่จับการเปลี่ยน URL ผ่าน History API ให้เอง ถ้าอยากควบคุมเอง เช่น รอให้ title เปลี่ยนก่อน ก็ปิดตัวเลือกนั้น แล้ว push event ตอน route เปลี่ยนเอง ไม่ว่าจะใช้วิธีไหน ต้องทดสอบว่า page_view ไม่ถูกนับซ้ำ

คำถามนี้คนสาย Frontend ตอบได้ดีกว่าคนสายการตลาด ใช้เป็นจุดเด่นได้

Q17หลัง deploy ตัวเลขในรายงานเพิ่มขึ้นเกือบ 2 เท่าทันที คิดว่าเกิดอะไรขึ้น
